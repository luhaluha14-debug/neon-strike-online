# SIGILFALL · 시길폴

브라우저에서 바로 돌아가는 **고속 주술 액션 FPS**입니다. PC와 모바일이 같은 코드베이스로 동작하고,
혼자서는 봇과, 온라인에서는 다른 사람과 싸웁니다.

- 총만 쏘는 게임이 아니라 **조준 → 이동 → 회피 → 술식 → 영역 전개**가 이어지는 능력전입니다.
- 캐릭터 4명은 기본 공격 방식부터 서로 다릅니다. 투사체, 근접 연격, 소환, 관통 저격.
- 궁극기는 전부 **영역(Domain)** 입니다. 짧고 강하게 규칙 자체를 바꿔 놓습니다.
- 등장하는 이름, 술식, 맵, 이펙트, 사운드는 전부 이 저장소에서 새로 만든 것입니다.
  특정 작품의 캐릭터·기술명·음악·모델을 가져다 쓰지 않습니다.

---

## 1. 실행

[Node.js](https://nodejs.org) 18 이상이 필요합니다.

```bash
npm install
npm start          # http://localhost:8080
```

브라우저에서 `http://localhost:8080` 을 엽니다. **PLAY** 는 봇 대전, **ONLINE** 은 사람과의 대전입니다.

같은 와이파이에 있는 친구는 서버 창에 표시되는 `http://192.168.x.x:8080` 주소로 들어오면 됩니다.
(Windows 방화벽 창이 뜨면 "개인 네트워크"를 허용해야 합니다.)

> 게임은 ES 모듈을 사용합니다. `index.html` 을 파일로 직접 여는 방식(`file://`)이 아니라
> 위처럼 서버를 띄워서 열어야 합니다.

## 2. 조작

### PC

| 키 | 동작 |
|---|---|
| `W A S D` | 이동 |
| `Shift` | 달리기 |
| `Space` | 점프 |
| `Ctrl` / `C` | 앉기 |
| 마우스 | 시점 |
| 좌클릭 | 기본 공격 |
| 우클릭 | 보조 공격 (캐릭터마다 다름: 응축 / 반격 / 표식 / 정밀 조준) |
| `Q` | 이동기 · 회피 |
| `1` `2` | 술식 |
| `E` | 궁극기 — 영역 전개 |
| `R` | 재집중 (주력 빠르게 회복) |
| `Tab` | 점수판 |
| `Esc` | 메뉴 |

키는 **설정 → 조작** 에서 전부 바꿀 수 있고, 게임 중에도 바꿀 수 있습니다.

### 모바일 (가로 화면 권장)

- **왼쪽 화면**: 아무 데나 누르면 그 자리에 가상 스틱이 생깁니다. 끝까지 밀면 달립니다.
- **오른쪽 화면**: 드래그로 시점, 짧게 탭하면 사격.
- **오른쪽 버튼 묶음**: 공격 · 보조 · 점프 · `Q` · `1` · `2` · `E`
- **왼쪽 아래**: 앉기 · `R`
- 버튼은 화면 크기에 맞춰 자동 배치되고, **설정 → 모바일** 에서 크기·투명도·왼손 모드를 바꿀 수 있습니다.

## 3. 모바일 조준 보정

모바일에서 가장 중요한 기능이라 규칙을 분명히 해 두었습니다. (`public/src/input/aimAssist.js`)

대상을 고를 때 보는 것:

1. 살아 있고 지금 공격할 수 있는 적인가
2. 조준점에서 몇 도 안에 있는가 (설정: **보정 범위**, 기본 26°)
3. 시야에 들어와 있는가
4. 벽 뒤에 있지는 않은가 — 가려져 있으면 절대 고르지 않습니다
5. 조준점에 가까운 적이 우선, 같으면 가까운 적이 우선

그 다음에 하는 일:

- 초당 회전량에 **상한**이 있습니다. 따라붙을 수는 있어도 순간적으로 달라붙지 않습니다.
- 플레이어가 직접 화면을 문지르는 동안에는 보정이 40%로 약해집니다. **수동 조준이 항상 우선**입니다.
- 조준점 근처를 지나갈 때는 스와이프에 약한 마찰이 걸려 지나치지 않게 도와줍니다.
- 대상이 죽거나 숨거나 시야각을 벗어나면 즉시 놓고, 다음 프레임에 새 대상을 찾습니다.
- 투사체 캐릭터는 이동 예측을 **부분만** 반영합니다(70%). 완전 자동 조준이 아닙니다.
- **설정 → 조준** 에서 강도(0~100%)와 범위를 조절할 수 있고, 0으로 두면 완전 수동입니다.
- PC에서는 기본적으로 꺼져 있습니다. 마우스를 움직이는 순간에도 보정은 개입하지 않습니다.

## 4. 술사 4명과 부적

| | 이름 | 계열 | 기본 공격 | 특징 |
|---|---|---|---|---|
| **RIFT** | 하란 | 공간 조작 | 공간 파편 (투사체) | 순간이동, 끌어당기기, 직선 절단 |
| **BRAND** | 서결 | 저주 근접 | 저주 연격 (근접 부채꼴) | 반격, 돌진, 각인이 쌓일수록 강해짐 |
| **WARDEN** | 무이 | 사역 소환 | 주령탄 (약한 유도) | 표식, 사냥개 소환, 지역 봉쇄 |
| **VEIN** | 연하 | 혈술 저격 | 혈탄 (관통) | 체력을 대가로 쓰는 고화력, 정밀 조준 |

각 캐릭터는 `Q`(이동기) · `1`(술식) · `2`(강한 술식) · `E`(영역)을 가집니다.
전체 수치와 설명은 게임 안 **CHARACTERS** 화면과 `public/src/characters/roster.js` 에 있습니다.

**LOADOUT** 화면에서 술사마다 부적 하나를 지닐 수 있습니다. 능력을 더 주지 않고 수치만 조금 바꿉니다.

| 부적 | 효과 |
|---|---|
| 무각 | 보정 없음 |
| 질주 | 이동 속도 +6%, 이동기 쿨다운 -1초 |
| 항력 | 최대 체력 +12%, 받는 피해 -4% |
| 순환 | 주력 회복 +30%, 술식 쿨다운 -8% |
| 의식 | 궁극기 충전 +18%, 영역 지속 +0.8초 |

체력·쿨다운·받는 피해·궁극기 충전·영역 지속은 **서버가 직접 적용**합니다. 클라이언트가 수치를 지어낼 수 없습니다.

### 영역 (Domain)

궁극기는 전부 영역입니다. 게이지는 피해를 주고 받고, 처치하면서 찹니다.
영역은 6~7초로 짧고, 안에서는 규칙이 바뀝니다.

| 캐릭터 | 영역 | 안에서 일어나는 일 |
|---|---|---|
| RIFT | 함몰 좌표 | 적 감속 + 지속 피해, 내 쿨다운 2배 회복, 끝날 때 중심으로 함몰 |
| BRAND | 격돌 영역 | 나를 따라다님. 근접 피해 +55%, 흡혈, 적 위치 노출 |
| WARDEN | 군세 영역 | 사역물 3기 소환, 적은 주력을 회복하지 못함 |
| VEIN | 적하 영역 | 적은 계속 출혈, 내가 준 피해의 45%를 회복 |

## 6. 봇

혼자 할 때도, 온라인 방에 사람이 모자랄 때도 봇이 들어옵니다.
달려들기만 하는 봇이 아니라 이동·엄폐·회피·술식·궁극기를 씁니다.

- 길찾기: 맵마다 만들어 두는 내비게이션 격자 위에서 A\* 로 움직입니다.
- 교전: 적정 거리를 유지하며 좌우로 돌고, 사격은 버스트로 끊습니다.
- 엄폐: 체력이 떨어지면 지금 보고 있는 적의 시선이 끊기는 칸으로 물러납니다.
- 술식: 사거리와 각도가 맞을 때만 쓰고, 궁극기는 영역에 적이 들어올 때만 씁니다.
- 잔영(WARDEN의 `Q`)에 속아 엉뚱한 곳을 쏩니다.
- 난이도 **쉬움 / 보통 / 어려움** 은 조준 오차, 반응 시간, 사격 지속, 술식 사용 빈도, 회피 성향을 바꿉니다.

## 7. 온라인

- **빠른 참가** — 사람이 있는 공개 방에 들어가고, 없으면 새로 만듭니다. 공개 방은 봇으로 채워져 바로 싸울 수 있습니다.
- **방 만들기** — 4자리 코드를 친구에게 알려주면 됩니다. 방장이 모드·맵·봇 채우기를 정하고 시작합니다.
- 경기 중에 들어와도 바로 합류합니다.

### 판정 방식

각자 자기 캐릭터를 움직이고, "이걸 맞혔다"고 서버에 알립니다. 서버는 모든 주장을 검사합니다.

- 쏜 방향이 다른 사람들에게 보이던 시선과 일치하는가
- 거리와 사거리가 맞는가
- 최근 0.45초 사이 대상의 실제 위치 중 하나와 조준선이 맞는가
- 그 사이에 벽이 없는가
- 연사 속도, 쿨다운, 궁극기 게이지가 허용하는가
- 그 술식이 낼 수 있는 최대 피해를 넘지 않는가

통과한 주장만 피해가 됩니다. **체력, 피해, 처치, 점수, 부활, 궁극기 게이지는 전부 서버가 정합니다.**
다른 사람은 약 0.11초 전 위치로 보간해서 부드럽게 보여줍니다.

**한계**: 이 구조는 에임봇을 막지 못합니다. 완벽하게 조준하는 클라이언트는 실제로 맞히기 때문에,
서버가 잘하는 사람과 스크립트를 구분할 수 없습니다. 경쟁 환경으로 키우려면 이동까지 서버가 계산하는
구조와 신고/제재 기능이 추가로 필요합니다.

## 8. 성능

- 처음 실행할 때 기기(모바일 여부, 코어 수, 메모리, 픽셀 비율)를 보고 그래픽 프리셋을 **자동 선택**합니다.
- 프레임이 목표치 아래로 계속 떨어지면 **그림자 → 해상도 배율 → 파티클 → 프레임 제한** 순으로 한 단계씩 자동으로 낮춥니다. (설정에서 끌 수 있습니다.)
- 직접 조절할 수 있는 항목: 품질 프리셋, 해상도 배율, 그림자, 파티클, 프레임 제한, 시야각, 화면 흔들림.
- 맵은 재질별로 인스턴스 하나에 모아 그리고, 파티클은 점 하나로 합쳐 그립니다.

## 9. 폴더 구조

```
sigilfall/
  public/
    index.html            화면 구조(HUD·메뉴)와 부트스트랩
    styles/ui.css         인터페이스 전체 스타일
    src/
      core/               엔진, 설정, 수학, 성능 감시
      input/              입력 관리자, 키보드/마우스, 조준 보정
      mobile/             터치 컨트롤(스틱·시점·버튼 배치)
      world/              맵 데이터, 충돌, 지형 생성, 내비게이션 격자
      combat/             전투 전반 — 파이터, 물리, 술식 실행, 투사체,
                          지역기, 영역, 소환물, 이펙트, 게임 필, 뷰모델
      characters/         술사 데이터 (roster.js 하나)
      ai/                 오프라인 봇
      game/               게임 규칙, 매치 진행, 플레이어 조작
      ui/                 HUD, 메뉴, 설정 화면, 화면 전환
      audio/              Web Audio 합성 사운드
      net/                온라인 클라이언트, 로비/방 화면
  server/
    server.js             HTTP + WebSocket 진입점
    static.js             정적 파일 (three.js는 node_modules에서 직접 제공)
    hub.js                접속·방 목록·매치메이킹
    room.js               방 하나의 규칙과 판정 (권위 서버)
    bot.js                서버에서 도는 봇
    shared.js             클라이언트와 같은 데이터 모듈을 그대로 불러옴
  test/                   테스트
```

서버는 맵·캐릭터·규칙을 **클라이언트와 같은 파일에서** 불러옵니다(`server/shared.js`).
수치를 한 곳에서만 고치면 양쪽이 항상 같은 기준으로 판정합니다.

### 밸런스는 측정해서 맞췄습니다

봇만 넣은 개인전을 맵 3개에서 돌려 캐릭터별 처치·피해·명중률을 비교했습니다.
근접(BRAND)이 거리를 좁히지 못해 피해량이 절반에 그쳤고, 그래서 이렇게 고쳤습니다.

- 쇄도 중에는 받는 피해 -40% (데이터의 `armor` 값 하나로, 서버도 같은 값을 적용)
- 충격 각인 사거리 9m → 13m: 중거리에서 압박하고 진입을 여는 수단
- 체력 252, 이동 속도 7.7로 상향
- 봇이 근접 캐릭터를 잡으면 멀리서 원을 그리지 않고 달려들도록 수정

고친 뒤 다시 측정한 결과입니다. K/D 편차가 1.24에서 0.44로 줄었습니다.

| 술사 | 처치 | 사망 | K/D | 봇당 피해 | 명중률 |
|---|---|---|---|---|---|
| WARDEN | 30 | 24 | 1.25 | 1085 | 41% |
| RIFT | 26 | 25 | 1.04 | 1262 | 43% |
| VEIN | 12 | 13 | 0.92 | 812 | 33% |
| BRAND | 25 | 31 | 0.81 | 591 | 90% |

직접 돌려 볼 수 있습니다.

```bash
node sigilfall/test/balance.cjs                    # 맵 3개, 각 50초
node sigilfall/test/balance.cjs --map market --seconds 90
```

봇끼리의 결과는 사람이 직접 플레이할 때와 다릅니다(엄폐, 쇄도 타이밍, 반격은 사람이 훨씬 잘 씁니다).
그래서 봇 수치는 "한쪽이 절반밖에 못 싸우고 있는가"를 보는 용도로만 썼습니다.

### 캐릭터 추가하기

`public/src/characters/roster.js` 에 항목 하나를 추가하면 끝입니다.
HUD 아이콘, 쿨다운 표시, 터치 버튼, 봇의 사용 판단, 서버 검증까지 전부 데이터를 읽어 동작합니다.
완전히 새로운 동작이 필요할 때만 `combat/abilities.js` 에 `<kind>Kind()` 를 하나 추가하면 됩니다.

기존 종류: `projectile` `hitscan` `melee` `dash` `blink` `zone` `buff` `summon` `parry` `ads` `charge` `domain`

## 10. 테스트

```bash
npm test
```

맵(스폰 지점이 막혀 있지 않은지, 모든 스폰이 서로 걸어서 닿는지), 캐릭터 밸런스(기본 공격 DPS 대역,
강한 술식에 대가가 있는지, 주력이 무한하지 않은지), 전투 수식, 서버 규칙(명중 검증·연사 제한·팀킬 불가·
쿨다운·궁극기 게이지·점수·부활·잘못된 패킷)을 노드에서 검사합니다.

브라우저까지 돌려 보는 테스트도 있습니다. 서버를 켠 상태에서:

```bash
npm i -D playwright
npm run test:browser                      # 아래 셋을 모두 실행

node sigilfall/test/browser-smoke.cjs     # 4캐릭터 실제 전투 + 온라인 2인 대전
node sigilfall/test/browser-ui.cjs        # 메뉴 → 캐릭터 → 부적 → 설정 → 매치 → 일시정지 → 결과
node sigilfall/test/browser-pc.cjs        # 실제 키보드/마우스 이벤트, 키 재설정, 부활
node sigilfall/test/browser-touch.cjs     # 터치 버튼, 가상 스틱, 조준 보정 규칙
node sigilfall/test/browser-abilities.cjs # 4캐릭터 × 6술식을 실제로 시전하고 결과 확인
```

`--mobile` 을 붙이면 모바일 화면 크기로 돌립니다. playwright가 없으면 그냥 건너뜁니다.

## 11. 인터넷에 공개하기

`render.yaml` 이 들어 있어 [Render](https://render.com) 에서 **New → Blueprint** 로 바로 배포됩니다.
직접 설정한다면 Build `npm install`, Start `npm start`, 포트는 `PORT` 환경변수를 씁니다.
Fly.io, Railway 등 다른 Node 호스팅도 같은 방식으로 동작하고, 접속은 자동으로 `wss://` 를 사용합니다.

무료 플랜에서는 한동안 접속이 없으면 서버가 잠들어 첫 접속이 느릴 수 있고,
서버가 재시작되면 진행 중이던 방은 사라집니다.
