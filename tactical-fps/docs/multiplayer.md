# 멀티플레이

데스매치(최대 8명)와 5대5 라운드전(최대 10명)을 사람끼리 함께 플레이합니다. 빈 자리는 봇이 채웁니다.

## 구조 — 방장 브라우저가 경기를 진행

```
방장 브라우저 (기존 게임 전체: 봇 AI · 규칙 · 판정 · 경제 · C4)
   │  snapshot 20/s · 경기 상태 4/s · 사격 결과 · 스폰 · 구매 응답
   ▼
릴레이 서버 (server/mp, Render 무료) — 방 관리와 메시지 중계만
   ▲
   │  자기 캐릭터 상태 30/s · 사격 · 구매 · 투척
멤버 브라우저 (자기 이동·무기·시점은 직접, 나머지는 방장이 보낸 그대로)
```

- **방장(host)**: 싱글플레이와 같은 게임을 그대로 돌립니다. 다른 사람은 각자 **봇 하나를 대신 조종**합니다(`Bot.remote`): AI가 꺼지고, 그 사람이 보낸 위치·시점·앉기·사용 키가 그 봇에 적용됩니다. 매치 명단·점수·돈·C4·사격 판정은 원래 코드가 그대로 처리합니다.
- **멤버(client)**: 자기 캐릭터의 이동과 무기는 자기 화면에서 바로 움직입니다(입력 지연 없음). 다른 사람과 봇은 방장의 스냅숏을 100 ms 뒤에서 보간해 그립니다(`Puppets`). 체력·사망·스폰·돈·라운드·점수판은 방장이 보낸 값 그대로입니다(`Mirror`: 점수판·HUD 코드는 그대로 쓰고, 자기 id만 `'local'`로 바꿔 받음).
- **사격**: 멤버가 쏜 탄은 시작점·방향·무기만 방장에게 갑니다. 방장은 그 멤버가 보던 시점으로 다른 캐릭터들을 되돌려(최대 0.3초, `LagCompensation`) 판정하고, 피해를 주고, 모두에게 결과(트레이서·혈흔·소리)를 보냅니다. 맞춘 사람에게는 히트마커가 갑니다.
- **검사**: 방장은 멤버 보고를 그대로 믿지 않습니다. 한 번에 6 m 넘는 이동은 거부하고 제자리로 돌려보냅니다. 탄은 다음 조건을 확인한 뒤에만 판정합니다.
  - 무기가 그 멤버의 것인지
  - 연사 속도를 넘지 않는지 (네트워크로 몰려 오는 경우를 위해 8발까지 버스트 허용)
  - 쏜 위치가 캐릭터 눈 위치에서 3 m 안인지
  - 라운드가 진행 중인지
  - 구매·투척은 방장 쪽 돈·소지품으로만 처리합니다.
- **릴레이**는 게임 내용을 읽지 않습니다. 멤버는 방장에게만, 방장은 멤버 한 명이나 전체에게만 보낼 수 있고, 보낸 사람 id는 서버가 붙입니다. 다른 사이트에서 접속(Origin), 32 KB 넘는 메시지, 초당 120개 넘는 메시지는 거부합니다. 응답 없는 연결은 15초마다 정리합니다.

## 방

- **빠른 참가**: 같은 모드의 빈자리 있는 방으로, 없으면 새 방(내가 방장).
- **방 만들기 / 코드로 참가**: 5자리 코드(헷갈리는 0·O·1·I·L 제외)를 친구에게 알려 줍니다. 없는 코드(모두 나가 사라진 방 포함)는 "만료되었거나 틀린 코드"로 안내합니다.
- **방 목록**: 릴레이의 `GET /mp/rooms`(코드·모드·맵·인원·정원, 이름은 없음). 빠른 참가가 이미 모든 방을 대상으로 하므로 새로 공개되는 정보는 없습니다. 이 경로가 없는 이전 버전 릴레이에서는 "방 목록을 받지 못했습니다"로 표시되고 나머지 기능은 그대로입니다.
- **팀 표시**: 라운드전에서 방장이 경기 상태(`match`)에 `who`(멤버 id → 팀)를 붙여 보내고, 방 정보에 BLUE/RED로 표시합니다.
- **연결 끊김**: 싱글플레이로 돌아오고 로비·멀티플레이 탭에 안내, 같은 방이 남아 있으면 **같은 방에 다시 참가**로 돌아갑니다(새 방장 체제의 새 경기).
- 맵과 모드는 방장이 방을 만들 때의 것입니다. 방에 있는 동안 모드·맵·경기 옵션은 잠깁니다.
- 팀전: 방장은 BLUE, 다음 사람부터 사람이 적은 팀으로(1:1이면 RED). 데스매치: 방장 + 봇 7명 중 사람이 봇 자리를 맡음.
- **방장이 나가면** 가장 먼저 들어온 사람이 방장이 되고 경기는 처음부터 다시 시작합니다(진행 중이던 상태는 떠난 방장의 브라우저에 있었으므로 이어받을 수 없음).
- 방장 탭이 숨겨져도(다른 탭으로 전환) Worker 타이머로 경기를 계속 진행합니다(화면은 그리지 않음).

## 실행

- 로컬: `npm run build && npm run build:mp && npm run start:mp` → http://localhost:8080 (게임 + `/mp`). 개발 서버로는 릴레이를 띄운 채 `GRID_MP_PROXY=http://127.0.0.1:8080 npm run dev`.
- Render: `render.yaml`의 `tactical-fps-mp`(무료 웹 서비스). 그 주소에서 멀티플레이가 됩니다. 정적 사이트 `tactical-fps`는 릴레이가 없어 멀티플레이 탭에 "서버 응답 없음"이 보입니다 — 빌드 시 `VITE_MP_URL=wss://<릴레이 주소>/mp`를 주면 정적 사이트에서도 그 릴레이로 접속합니다(릴레이의 `GRID_MP_ORIGINS`에 정적 사이트 주소 필요, 이미 들어 있음).
- 무료 플랜은 15분 동안 접속이 없으면 잠들고, 첫 접속 때 깨어나는 데 1분 정도 걸립니다(참가 버튼이 최대 75초 기다림).

## 한계 · 위험

- **방장 권한**: 방장의 브라우저가 판정하므로 방장은 조작(치트)이 가능합니다. 친구끼리 하는 용도이며, 공정한 공개 매칭에는 서버 판정이 필요합니다(무료 서버 CPU로는 봇 판정이 어려워 이번 구조를 택함).
- 방장은 지연이 없어 조금 유리합니다. 멤버의 지연은 지연 보정(최대 0.3초)으로 줄이지만 0이 되지는 않습니다.
- 방장이 나가면 경기가 새로 시작됩니다.
- 방장 컴퓨터가 느리면 방 전체가 느려집니다(봇 AI와 판정을 방장이 모두 계산).
- 멤버 화면에서 내 탄이 상대 몸을 통과해 벽에 자국을 남길 수 있습니다(맞았는지는 방장 판정 → 혈흔·히트마커로 표시).
- 사람 이름표·음성·채팅·친구 목록·전적 저장 없음. GRID 크레딧은 각자 브라우저의 오프라인 기록입니다(서버 계정은 꺼져 있음).
- 트래픽: 10명 방이면 릴레이에서 나가는 양이 초당 수백 KB입니다. 무료 플랜의 월 전송량 안에서 수십~백여 시간 분량.
