# GRID — 전술 FPS (`tactical-fps`)

웹 브라우저에서 실행되는 5v5 라운드 기반 폭탄 해체 전술 FPS의 기반 프로젝트입니다.
현재 단계: Blender 맵 2개, 무기 6종, 봇 데스매치·훈련장, 5대5 팀전(라운드 경제·구매, C4 폭파 목표, 투척 장비, 봇 전술).
모든 콘텐츠(맵, UI 등)는 오리지널입니다.

## 실행

```bash
cd tactical-fps
npm install
npm run dev        # http://localhost:5173
npm run build      # 타입 검사 + 프로덕션 빌드 (dist/)
npm run preview    # 빌드 결과 확인
npm test           # 회귀 테스트 (아래 "테스트" 참고)
```

처음 화면은 **GRID 로비**입니다: **PLAY**(5대5 라운드전 / 봇 데스매치 선택 → 플레이 탭) · **MULTIPLAYER**(멀티플레이 탭) ·
**ARSENAL**(무기 탭) · **TRAINING**(훈련장 → 플레이 탭) · **SETTINGS**(설정 탭). 경기를 시작한 뒤에는 **RESUME**(계속하기)이 생깁니다.
PLAY·MULTIPLAYER가 큰 버튼, ARSENAL·TRAINING·SETTINGS가 그 아래 한 줄입니다. 아래 줄에 준비 상태·온라인 서버 상태·작전 구역(배경 맵 이름)이 보입니다.
로비 배경은 지금 불러온 맵(예: MAP 02 · 서울)을 **로비 전용 카메라**로 본 장면이고, 앞에 기존 요원 모델(BLUE `operator.glb`)이 서 있습니다.
구도는 맵마다 `src/maps.ts`의 `lobby`(카메라 위치·방향, 요원 위치·방향)로 정합니다: MAP 01은 공격 스폰에서 중앙 골목, MAP 02는 공격 스폰에서 대로 끝의 남산·타워.
`lobby`가 없는 맵은 스폰 지점 중 시야가 가장 트인 방향을 자동으로 고릅니다. 맵을 불러올 때마다 구도 전체(카메라·요원)를 새로 정하고, 로비 그림에서는 봇·표적·다른 플레이어를 숨깁니다. 정지 화면이므로 바뀔 때(로비 진입·창 크기·맵·모델 로딩)만 한 번 그리고,
매 프레임 다시 그리지 않습니다. 새로 받는 파일은 없습니다(맵과 요원 모델은 게임이 이미 불러오는 것). 게임 카메라는 건드리지 않아 게임에 들어가면 그대로입니다. 메뉴 머리의 **◂ 로비**, 결과 화면의 **로비** 버튼으로 로비에 돌아옵니다.
온라인 방에 있으면 로비에 방 코드·인원·**경기 입장**·**방 나가기**가 보이고, 방을 나갈 때까지 PLAY·TRAINING은 잠깁니다.

플레이 탭의 **플레이** 버튼을 누르면 마우스가 잠기고 바로 플레이할 수 있습니다.
메뉴는 **플레이**(맵 선택) · **무기**(시작 무기 선택) · **설정**(화질, 프레임 제한, 성능 정보) · **조작** 탭으로 되어 있고,
Esc로 언제든 돌아와 **계속하기**를 누를 수 있습니다. 맵 · 프레임 제한 · 화질 선택은 선택은 브라우저에 저장되며,
맵을 바꿔도 페이지를 새로 열지 않으므로 **모든 맵이 같은 링크**를 씁니다.
(예전 `?map=` 링크도 한 번 적용된 뒤 주소에서 지워집니다.)

**프레임 제한**: 기본값 "최대"는 모니터 주사율 그대로(144/165/240Hz 모니터면 그만큼) 그립니다.
브라우저는 화면을 주사율보다 자주 갱신하지 않으므로 그 이상은 의미가 없고, 주사율 밖에서
억지로 돌리면 오히려 화면 갱신이 굶어 끊깁니다(측정으로 확인). 주사율 이상이 꼭 필요하면 브라우저를
`--disable-frame-rate-limit` 로 실행해야 합니다. 프레임이 주사율보다 낮다면 **화질 "낮음"**을 고르세요.

**화질 "자동 (권장)"** (기본값, `core/AutoQuality.ts`): GPU 이름은 보지 않고 기기가 알려 주는 능력만으로 시작 화질을 정합니다.
- **시작 화질**: 성능 경고 없이 WebGL이 동작하는지, 최대 텍스처 크기(8192 미만이면 낮음), CPU 코어 4개 이하, 메모리 2 GB 이하, 터치 화면을 봅니다. 해당하면 **낮음**, 아니면 **중간**입니다. WebGL 정보를 못 읽으면 예전 규칙을 씁니다(코어 4개 이하·터치 → 낮음, 그 외 중간). **높음**은 측정으로만 올라갑니다.
- **측정**: 플레이 중(마우스가 잠긴 상태) 실제 프레임 시간만 잽니다. 메뉴·로비·숨긴 탭·로딩 중의 프레임은 세지 않고, 다시 플레이하면 5초 워밍업부터 시작합니다. 0.25초가 넘는 한 프레임(탭 전환·GC·셰이더 컴파일)은 그 구간을 버립니다.
- **낮추기**: 4초 구간 3개가 연속으로 느리면(평균 40 fps 미만, 또는 20프레임 중 1프레임이 1/24초보다 김) 그 자리에서 한 단계 낮춥니다. 구간 하나보다 짧은 일시적 저하는 많아야 구간 2개에 걸치므로 화질을 바꾸지 않습니다. 플레이 중에는 픽셀 비율·그림자·그림자 맵 크기만 바뀌고, 안티앨리어싱과 표면 셰이딩은 다음 로드부터 적용됩니다. 두 번째 변경은 30초 뒤에야 가능합니다.
- **올리기**: 플레이 중에는 올리지 않습니다. 4초 구간 3개가 연속으로 여유 있으면(평균 58 fps 이상, 1프레임/20 ≤ 1/40초) 다음 로드를 한 단계 높게 시작하도록 기억합니다. 한 번 느려서 낮춘 화질은 상한으로 기억해 다시 고르지 않으므로 화질이 오르내리기를 반복하지 않습니다.
- **수동 선택**: 낮음·중간·높음을 직접 고르거나 링크에 `?quality=`를 주면 측정하지 않고 그대로 씁니다. 다시 **자동**을 고르면 기억한 값(상한 포함)을 지우고 처음부터 측정합니다. F3 성능 정보에 현재 화질과 `(auto)` 여부가 표시됩니다.
- 이 기준값은 실제 GPU에서 측정해 정한 값이 아니라 **추정치**입니다. 테스트는 소프트웨어 WebGL에 프레임 시간을 넣어서 확인한 것입니다.

### 점프 · 버니합 · 공중 가속

이동은 120 Hz 고정 틱으로 계산합니다(`player/PlayerController.ts`, 수치는 `config.ts`의 `PLAYER_CONFIG`). 걷기·달리기·앉기·SR-01 조준 이동은 이전과 같습니다.

- **점프 입력 버퍼**: 착지 0.1초 전까지 누른 점프는 착지하는 틱에 바로 나갑니다(`jumpBuffer`). 누르고 있기만 해서는 다시 뛰지 않습니다(새로 눌러야 함).
- **버니합**: 착지하는 그 틱에 다시 뛰면 지면 마찰을 받지 않아 속도가 유지됩니다. 늦게 뛰면 그동안 마찰로 속도를 잃습니다. 앞(W)만 누르고 뛰면 달리기 속도(5.4 m/s) 그대로이며, 점프만 반복해서는 빨라지지 않습니다.
- **공중 가속 / 에어 스트레이프**: 공중에서는 지면과 다른 가속(`airAccel` 3)을 씁니다. 원하는 방향으로의 속도 성분을 `airWishSpeed`(0.9 m/s)까지만 보태므로, 옆 이동 키(A/D)와 같은 방향으로 마우스를 부드럽게 돌릴 때만 속도가 붙습니다. 키만 누르거나 너무 빨리 돌리면 붙지 않거나 줄어듭니다. 반대 방향 입력은 공중 브레이크가 됩니다.
- **최고 속도**: 공중 수평 속도는 9 m/s(`maxAirSpeed`)를 넘지 않고, 빨라질수록 한 번에 붙는 속도가 줄어듭니다(평지 측정: 1.5 rad/s로 돌리며 연속 합 → 6.1, 6.5, 6.9, … 8.5, 8.6 m/s).
- **점프 없이 떨어질 때**(난간·계단 아래)는 이전과 같은 공중 조작을 씁니다(`fallAccel`, `fallControl`).
- **벽 미끄러짐 수정**: 지면에서 벽에 비스듬히 달려 붙으면 벽을 따라 속도가 계속 붙던 문제(최대 약 10 m/s)를 고쳤습니다. 벽에 밀린 지면 틱은 그 틱 시작 속도나 이동 속도보다 빨라지지 않습니다.
- 화면 흔들림은 추가하지 않았습니다.

## 테스트 (회귀 검사)

```bash
npm test                    # 전체 (헤드리스 Chromium, 이 환경에서 약 수 분)
npm test -- ui body         # 파일 이름에 ui 또는 body가 들어간 것만
UPDATE_GOLDEN=1 npm test -- movement   # 의도한 변경 후 기준값 다시 기록 (diff를 꼭 검토)
```

처음 한 번은 브라우저가 필요합니다: `npx playwright install chromium`.
테스트는 Vite 개발 서버를 직접 띄우고, 개발 빌드가 노출하는 `window.game` / `window.vmCheck`로 게임을 조작합니다.
게임 코드는 테스트를 위해 바뀌지 않습니다. `playwright`는 devDependency라 배포 결과물(`dist/`)에 들어가지 않습니다.

- 무기를 바꿔도 각 무기의 탄약은 유지되고, 재장전 중에 바꾸면 재장전이 취소됩니다(탄약 손실 없음).
- 발사는 고정 틱(120Hz)에서 계산되어 프레임레이트와 무관하게 연사 속도가 정확합니다. 매 발마다 별도 레이캐스트를 합니다.
- 제자리에서는 첫 발이 조준점 정중앙에 맞고, 이동/점프 중에는 탄퍼짐이 커집니다 (`spread`).
- 반동: 발사할수록 위로 누적(AR-01 최대 6°, SMG-01 4.5°). 좌우는 무기마다 정해진 S자 경로를 따릅니다(AR-01은 오른쪽 → 왼쪽 → 오른쪽, SMG-01은 왼쪽부터 더 빨리 꺾임). 매번 같은 경로라 익혀서 마우스로 반대로 당길 수 있고, 그 위에 작은 무작위 흔들림만 더해집니다.
  사격을 멈추면 위아래뿐 아니라 좌우도 원래 조준점으로 부드럽게 돌아오며(SR-01은 볼트를 당기는 동안 조준경이 표적으로 복귀), 플레이어가 마우스로 이미 보정한 만큼은 되돌리지 않습니다. 피해·연사 속도·탄창은 바뀌지 않았습니다.
- **손**: 검은 전술 장갑 + 어두운 소매의 절차적 팔이 무기의 `gripAnchor`(오른손)와 `supportAnchor`(왼손)에 붙습니다.
  손잡이 크기에 맞춰 손가락 위치가 바뀌고, 검지는 방아쇠 위(총) 또는 고리 안(카람빗)에 들어갑니다. 한 손 무기는 왼팔을 숨깁니다.
- **적 추가 시**: `Damageable` 을 구현해 `game.hitscan.register(target)` 하면 벽 판정·거리 감소·부위 배율이 자동 적용됩니다.
- 개발 서버 콘솔에서 `game.debugShots = true` 로 매 발의 명중 결과를 로그로 볼 수 있습니다.

## 무기 구조

```
플레이어 입력 ─┐
               ├─▶ WeaponCommand { fire, reload, equipSlot, equipLast, inspect }
AI 봇 (예정) ──┘                 │
                                 ▼
                         WeaponSystem (로드아웃, 교체, 살펴보기)
                                 ▼
                         Weapon (탄약·연사·재장전·꺼내기 상태, 렌더링 없음)
                                 ▼  이벤트(onShot, onEquip …)
          Game ──▶ ViewModelLayer ──▶ WeaponView (GLB: AR-01 / SR-01 / M9, 임시 절차적 모델은 대체용)
                         │                 └─ 앵커: Grip_R, Grip_L, Muzzle, Magazine, Bolt
                         └──▶ FirstPersonArms (앵커 + HandGripProfile 로 손 모양 생성)
```

- 무기는 입력 장치를 모릅니다. `WeaponSystem.step(command, dt)` 에 같은 구조체만 넣으면 플레이어든 봇이든 똑같이 동작합니다.
- 근접 무기는 "탄창 0 + 사거리 1.9 m" 인 무기라서 사격·히트스캔·피해 코드를 그대로 씁니다.
- **1인칭 위치 조정**: `weapons.ts` 의 `view.pose` (position / rotation / scale). 코드 수정 없이 숫자만 바꾸면 됩니다.
  개발 서버에서는 콘솔에서 `game.viewModel.restPosition.set(x, y, z)` 로 바로 확인하고, `vmCheck()` 로 장갑 겹침과 카메라 근접을 측정할 수 있습니다.
- 애니메이션: 꺼내기·집어넣기, 재장전, 볼트 당기기(SR-01), 베기(카람빗), 살펴보기(F).
  무기를 바꾸면 들고 있던 무기가 먼저 화면 아래로 내려가고(최대 0.15초) 새 무기가 올라옵니다. 내려가는 시간은 새 무기의 꺼내기 시간 안에 들어가므로 사격 가능 시점은 그대로입니다(`ViewModelLayer` `setView(..., holster)`).
  꺼내기·집어넣기 동작은 종류마다 다릅니다(소총은 굴리며, SMG는 오른쪽에서, 권총은 총구부터, 산탄·저격은 무겁게, 칼은 뒤집으며). 사망·리스폰·방장 스폰 때는 진행 중인 교체·반동·착지 동작이 초기화됩니다.
  재장전도 종류마다 다르고 소리 시점에 맞춥니다: 소총(탄창 빼기 0.04, 넣기 0.81, 장전 손잡이), SMG(가볍게, 0.78에 탄창 치기, 왼손이 탄창 위치로 감), 권총(왼쪽으로 기울이고 총구 위, 0.72 탄창, 끝에 슬라이드), 산탄총(총구를 올리고 왼쪽으로 기울여 장전구가 보이게 하고 0.15·0.4·0.65 탄 넣을 때마다 밀기, 끝나면 펌프), 저격총(장전 동안 볼트 열림, 끝에서 닫힘).
  PIS-01·SG-01·SMG-01은 부품을 나눈 리그 파일을 써서 슬라이드·펌프·탄창·장전 손잡이가 실제로 움직입니다(아래 "움직이는 부품").
  사격 반응은 무기마다 다릅니다(`ViewModelLayer` 의 `SHOT_FEEL`): 소총은 고르게 밀리고(한 발 약 0.9°·6 mm), SMG는 작게 떨리고, 권총은 위로 튀고(약 2°, 거의 밀리지 않음), 산탄총·저격총은 크게 밀립니다(약 2°·13~15 mm). 매 발 작은 비틀림(0.4~0.8°)이 무작위 방향으로 들어갑니다.
  SG-01은 발사 후 펌프 소리(뒤 0.12~0.24초, 앞 0.30~0.40초)에 맞춰 왼손이 앞손잡이를 당겼다 밀고 총이 살짝 기웁니다(모델은 한 덩어리라 앞손잡이 자체는 움직이지 않음).
  이동 중 걸음마다 약간 기울고, 착지하면 잠깐 내려갔다 올라오며(약 7 mm), 서 있을 때는 숨쉬듯 아주 작게 움직입니다. 화면 흔들림은 추가하지 않았습니다.
  모델은 `animate(state)` 로 자기 부품(볼트 등)만 움직이고, 공통 동작은 `ViewModelLayer` 가 처리합니다.

### Blender 모델로 교체하기

1. 모델 좌표(게임 기준): 총구/칼날 방향 **-Z**, 위 **+Y**, 오른쪽 **+X**, 단위 m. 원점은 대략 손잡이 근처.
   Blender(Z-up)에서는 총구를 **+Y**, 위를 **+Z** 로 만들면 glTF 내보내기가 게임 기준으로 바꿔 줍니다.
2. 빈 오브젝트(Empty) 이름:
   - `Grip_R` — 오른손 위치. 로컬 +Y 가 손잡이 축(위), +Z 가 사수 쪽.
   - `Grip_L` — 왼손 위치 (총열 덮개 아래). 한 손 무기는 생략 → 왼팔 숨김.
   - `Muzzle` (총구 화염), `Magazine` (재장전 때 빠지는 부품), `Bolt` (볼트액션) — 있으면 사용.
3. 장갑 맞추기 (Custom Properties, glTF 내보내기에서 "Custom Properties" 체크):
   - `Grip_R` 에 `grip_width`, `grip_depth` (m), `grip_index` ("trigger" / "ring"), `wrist_lift` (m)
   - 무기 오브젝트에 `right_elbow`, `left_elbow` ([x, y, z]) — 팔이 모델을 관통할 때만
4. `public/weapons/` 에 GLB를 넣고 `weapons.ts` 의 `view` 를
   `{ kind: 'gltf', url: '/weapons/sr01.glb', fallback: 'sr01', pose: { … } }` 로 바꿉니다. 끝입니다.
   로딩 중에는 `fallback` 임시 모델이 보이고, 다 받으면 자동으로 바뀝니다 (`GltfWeaponView`).
   무기 로직(`Weapon`, `WeaponSystem`), 팔(`FirstPersonArms`), 공통 모션(`ViewModelLayer`)은 수정하지 않습니다.
5. 개발 서버 콘솔에서 `vmCheck()` 로 장갑이 모델에 묻히는지(mm)와 카메라에 너무 가까운지 확인하고 `pose` 를 조정합니다.

검증: 현재 SR-01 임시 모델을 브라우저에서 GLB로 내보낸 뒤 이 경로로 다시 불러와, 손 위치·손잡이 프로필·팔꿈치·볼트 동작·겹침 수치가
절차적 모델과 동일함을 확인했습니다.

## 사운드

오디오 파일은 없습니다. 모든 효과음은 `audio/weaponSounds.ts`의 레시피로 페이지 시작 직후(맵 다운로드 중)
한 번만 합성되고(약 0.3초, 여러 작업으로 나눔, 약 3 MB), 전투 중에는 미리 만든 버퍼를 재생만 합니다.

- 총성 = 날카로운 초기 파열음 + 본체(폭발음) + 작은 저음 + 기계음(노리쇠/리시버) + 어두운 잔향 꼬리 + 약한 초기 반사음.
  AR-01은 4가지, SR-01은 3가지 변형 + 재생 속도 ±2.5%·음량 변화로 연사해도 같은 소리가 반복되지 않습니다.
- 발사 1회 = 총성 1회 (무기 시스템의 `onShot` 이벤트에서만 재생). 탄착음은 거리만큼 늦고 작게 들립니다.
- 재장전 소리는 1인칭 탄창 애니메이션 시점(`sounds.reload`의 `at` 값)에 맞춰 나오고, 무기를 바꾸면 끊깁니다.
- SR-01 볼트 소리는 볼트 애니메이션(`animateBolt`)과 같은 시간표로 만들어집니다.
- 브라우저 정책상 첫 클릭/키 입력 전에는 소리가 나지 않습니다. 볼륨은 설정 → 사운드에서 바꾸고 저장됩니다.
- 무기별 소리는 `weapons.ts`의 `sounds` 항목에서 고릅니다 (게임 밸런스와 무관).

## 플레이어 체력 · 사망 · 리스폰

- **체력 100**: 기존 `PlayerController.health`를 그대로 씁니다. 플레이어는 `Damageable`로 맵의 `HitscanSystem`에 등록되어,
  다른 사수(나중의 봇)의 탄은 기존 벽 판정·부위 배율·거리 감소·무기 수치로 피해를 줍니다. 자기 탄은 맞지 않습니다(기존 규칙: 같은 id 'local').
  판정은 임시 캡슐(반지름 0.3 m, 앉으면 낮아짐): 위 14% 머리, 아래 50% 다리(팔다리 배율), 나머지 몸.
- **피격 표시**: 화면 가장자리 붉은 기운(피해량에 비례, 0.55초), 조준점 둘레의 붉은 호가 총알이 온 방향을 가리킴, 체력 칸이 잠깐 붉어짐.
- **사망**: 체력 0에서 사망. 더 이상 맞지 않고(총알 통과), 이동·시점·사격·무기 전환·F4가 막히며, 1인칭 무기와 하체를 숨기고 시점이 바닥으로 기웁니다.
  화면 위쪽에 "사망 · 리스폰까지 n초" 표시.
- **리스폰**: 3초 뒤(게임 시간, 일시정지 중에는 멈춤) 현재 맵의 스폰 지점에서 체력 100. 기본 스폰이 지형과 겹치면 다음 스폰 지점을 씁니다.
  탄약은 기존 F4 리스폰과 같은 규칙으로 초기화되고, 훈련 표적도 초기화됩니다. 리스폰 후 1초 동안은 피해를 받지 않습니다(스폰 보호).
- **아직 없는 것**: 플레이어를 공격하는 적·봇(그래서 지금 실제 플레이에서는 피해를 받을 일이 없습니다), 팀·라운드, 온라인 동기화(이 프로젝트에는 네트워크 코드가 없음).

## 봇 데스매치 (기본 모드)

같은 곳에서 바꾸며, 바꾸면 경기가 새로 시작됩니다(`tactical-fps.match.v1`에 저장, 기존 설정 형식 유지). 링크의 `?mode=training|deathmatch|team`이 우선합니다.

- **봇** (`ai/Bot.ts`): 플레이어와 같은 `PlayerController`(이동·충돌)와 `WeaponSystem`(AR-01: 연사·반동·탄퍼짐·재장전·히트스캔·피해)을 같은 명령 구조로 씁니다.

  - 끼임: 1초 가까이 제자리면 점프하고 새 경로. 봇끼리는 서로 밀어내 겹치지 않게 합니다.

## 5대5 라운드전 (팀전)

**BLUE**(나 + 아군 봇 4) 대 **RED**(적 봇 5). 먼저 **승리 라운드**(3/5/7/10, 기본 5)에 닿은 팀이 이깁니다.
기본 목표는 **C4 폭파**(아래 'C4 폭파 목표'), 옵션의 **전멸전**을 고르면 아래의 라운드 규칙(전멸 / 시간 종료 시 생존자 수)으로 진행합니다.
라운드 시간(1/2/3분, 기본 2분)과 승리 라운드는 팀전을 고르면 보이는 옵션에서 바꾸며, 개인전 옵션(봇 수·제한 시간·목표 킬)과 따로 저장됩니다.

- **라운드 흐름** (`game/TeamMatch.ts`, 화면과 분리된 규칙): 작전 준비(15초 구매 시간, 모두 스폰에서 정지·사격 불가, 라운드 시계와 별개) → 진행 → 결과 표시(4초) → 다음 라운드.
  - 전멸한 팀이 지고, 양 팀이 같은 틱에 전멸하면 무승부. 시간이 다 되면 생존자가 많은 팀이 이기고 같으면 무승부. 무승부는 어느 팀에도 점수를 주지 않습니다.
  - 킬은 라운드 진행 중에만 집계됩니다. 같은 팀 킬은 인정하지 않습니다(아군 사격이 꺼져 있어 실제로는 생기지 않음).
- **재생성 없음**: 라운드 중 죽으면 그 라운드가 끝날 때까지 쓰러진 채로 남습니다. 플레이어는 1.5초 뒤 살아 있는 아군 뒤에서 관전하며(클릭으로 아군 전환), 다음 라운드에 모두 같은 상태로 다시 시작합니다(체력·탄약·AI 기억·효과 초기화).
- **아군 사격 없음**: 같은 팀이 쏜 탄은 아군을 **통과**합니다(맞지도 막히지도 않음). 그래서 아군 바로 뒤의 적은 맞습니다. 적에 대한 피해 계산은 개인전과 같습니다.
- **봇**: 개인전과 같은 AI(이동·길찾기·시야·카운터 스트레이핑·정지 사격·수색)에 팀 구분만 더했습니다. 다른 팀만 적으로 보고, 적이 안 보이면 상대 진영 쪽으로 순찰합니다.
  팀마다 군복 색과 **헬멧 띠·완장 색**(파랑/빨강)이 달라 멀리서도 구분됩니다.
- **스폰**: BLUE는 맵의 공격(ATK) 스폰, RED는 방어(DEF) 스폰 5곳(두 맵 모두 서로 57 m / 94 m 떨어짐). 서 있을 공간·내비 격자를 확인하고, 부족하면 근처 걸을 수 있는 칸으로 채웁니다.
- **HUD**: 위 가운데 BLUE·RED 라운드 승수, 라운드 번호와 남은 시간(준비 중엔 준비 시간), 팀별 생존 인원, 라운드 결과 안내, 킬 피드(팀 색). **Tab**은 팀별 점수판(이름·킬·데스).
  경기가 끝나면 승리 팀, 최종 점수, 라운드별 결과(승리 팀·전멸/시간)와 팀별 표, **다시 시작**.

### 킬 확인음

경기가 실제로 처치를 인정한 경우에만(데스매치: 자살·경기 종료 후 제외, 팀전: 진행 중인 라운드의 적만) 짧은 확인음이 한 번 납니다.
명중만 한 경우, 봇끼리의 처치, 이미 쓰러진 대상, 훈련 표적에는 나지 않습니다. 처치마다 고유 키로 한 번만 재생합니다(`src/game/KillConfirm.ts`).
멀티플레이에서는 방장의 경기가 인정한 멤버의 처치를 방장이 그 멤버에게만 처치 번호와 함께 보내고(`kill` 메시지), 멤버는 번호마다 한 번만 재생합니다.
소리는 다른 효과음처럼 코드로 합성하며(`kill.confirm`, 파일 없음) 오디오 초기화와 효과음 볼륨 설정을 따릅니다.
발사음(`*.shot`, 발사 그룹)·명중음(`hit.body`/`hit.head`, 충격 그룹)·킬 확인음(`kill.confirm`, 전용 그룹 최대 2개)은 서로 다른 소리이고,
킬 확인음은 전용 그룹이라 연사 중 탄착음이 많아도 끊기지 않습니다. 멀티플레이 멤버도 방장이 명중을 판정하면 단독 플레이와 같은 명중음을 듣습니다.
히트마커와 명중음은 한 발에 한 번입니다(`src/game/HitFeedback.ts`): 산탄총 한 발의 펠릿 여러 개가 맞아도, 멤버가 방장에게서 펠릿마다 명중 메시지를 받아도 한 번만 나옵니다(머리 명중이 하나라도 있으면 머리 명중음, 처치가 있으면 처치 마커).
다른 사람의 총소리는 거리에 따라 작아지고 늦게 들리며, 10 m부터는 고음이 깎여 둔하게 들립니다(50 m 약 7 kHz, 100 m 약 3 kHz).

### 대결 포기 (팀전 전용)

- 팀전 중 **Esc** 일시정지 메뉴의 **대결 포기** → 확인 창("정말 대결을 포기하시겠습니까? 포기하면 현재 대결은 패배 처리됩니다.")에서 **대결 포기** / **계속 플레이**.
  계속 플레이는 창만 닫고 경기로 돌아갑니다(아무 상태도 바뀌지 않음). 개인전·훈련장과 경기가 끝난 뒤(결과 화면)에는 버튼이 없습니다.
- 확정하면 경기가 즉시 패배로 끝나고 결과 화면에 **대결 포기 - 패배**가 뜹니다(플레이어 1명 + 봇이라 투표 없이 즉시 확정).
  남은 라운드를 진행한 것으로 치지 않고, 라운드 보상·처치 보상을 새로 주지 않으며, 이미 정산된 라운드는 그대로입니다(`TeamMatch.forfeit`).
  설치된 C4·타이머·설치/해체 진행·투척물·실명은 정리되고, 봇 명령과 입력이 해제되며 마우스 잠금이 풀립니다. 두 번 눌러도 한 번만 처리됩니다.
  **다시 시작** / **메뉴**는 새 경기를 처음부터 시작합니다.

### 라운드 경제 · 장비 구매 (팀전 전용)

- **흐름**: 작전 준비(구매) → **출격 확정** 또는 구매 시간(15초) 종료 → 라운드 → 결과 → 보상 정산 → 다음 작전 준비.
  작전 준비 중 **B**로 구매 메뉴를 열고 닫습니다(마우스 잠금이 풀리며, 닫으면 다시 잡힘. Esc는 일시정지 메뉴로). 메뉴가 열려 있어도 구매 시계는 흐르고, 시점·사격 입력은 게임에 전달되지 않습니다.
  **출격 확정**을 누르면 다음 틱에 모두(플레이어·봇 9명) 동시에 라운드가 시작됩니다. 구매 시간이 다 되어 메뉴가 닫히면 마우스를 다시 잡을 클릭이 필요해, 일시정지 메뉴에서 **계속하기**를 누를 때까지 게임이 기다립니다.
  라운드 중·사망(관전) 중·결과 화면에서는 구매할 수 없습니다.
- **경제 규칙** (`game/Economy.ts`의 `ECONOMY` 한 곳에서 관리): 시작 $3,000, 최대 $16,000, 라운드 승리 $3,000,
  패배 $1,900 + 연패마다 $500(최대 $3,400: 1·2·3·4연패 = $1,900·$2,400·$2,900·$3,400), 무승부 양 팀 $1,900(연패 수 유지), 적 처치 $200.
  승리하면 그 팀의 연패 수는 0. 라운드 보상은 라운드가 결정될 때 **한 번만**, 처치 보너스는 라운드마다 같은 희생자에 대해 **한 번만**(아군·자살·라운드 밖 처치는 없음) 지급됩니다.
  자금은 0 미만·최대 초과가 될 수 없습니다.
- **라운드 사이 장비** (`Economy.ts`의 `LOADOUT_RULES` 한 곳): 라운드가 끝날 때 **살아 있으면** 주무기·보조무기(남은 탄창·예비탄 그대로)·방탄 조끼(남은 AP)·쓰지 않은 투척물을 그대로 가지고 다음 라운드를 시작하고,
  **죽었으면** 모두 잃고 기본 지급(나이프)으로 시작합니다. 이월된 장비는 다시 지급·청구되지 않으며, 이월된 무기를 교체할 때는 환불이 없습니다(그 라운드에 산 것만 환불). 하프타임 공수 교대와 새 경기는 기본 지급부터.
- **장비 카탈로그** (`weapons/catalog.ts`, 가격·지급 무기·사용 가능 여부를 한 곳에서 관리, 구현된 무기의 탄약·연사는 `weapons.ts` 정의에서 읽음):

### C4 폭파 목표 (팀전 기본)

팀전 옵션 **목표**: `C4 폭파`(기본) 또는 `전멸전`(이전 규칙). 링크에 `?objective=elimination|bomb`을 붙이면 이번 접속에서만 바꿉니다.
규칙 수치는 모두 `config.ts`의 `BOMB_CONFIG`.

- **팀과 사이트**: 1라운드는 BLUE(나 + 아군 봇) 공격·RED 방어. 폭탄 사이트는 맵 파일에서 읽습니다
  (창고: `Zone_A_Site_PlantArea`·`Zone_B_Site_PlantArea`, 서울: `BombSite_A/B_PlantZone_Volume`; `maps.ts`의 `bombSitePattern`). 바닥 표시처럼 얇은 영역은 3 m 높이로 늘립니다.
- **운반**: 라운드마다 공격팀 한 명이 C4를 가집니다(라운드마다 순서대로 돌아감). 운반자가 죽으면 그 자리에 떨어지고, 공격팀이 1.2 m 안에 오면 줍습니다(방어팀은 못 주움).
- **설치**: 사이트 안에서 **E**(조작 설정 'C4 설치 / 해체')를 3.2초 누르고 있기. 움직이거나(0.6 m/s 초과), 피해를 입거나, 죽거나, 사이트를 벗어나거나, 키를 떼면 취소되고, 취소 후에는 키를 한 번 뗐다가 다시 눌러야 합니다. 설치자 +$300.
- **타이머·해체**: 설치 후 라운드 시계는 멈추고 40초 뒤 폭발. 방어팀이 폭탄 1.6 m 안에서 E를 7초 누르면 해체(같은 취소 조건), 해체자 +$300.
- **승패**: 설치 전 — 공격팀 전멸 → 방어 승, 방어팀 전멸 → 공격 승, 동시 전멸 → 무승부, 시간 종료 → 방어 승.
  설치 후 — 공격팀이 전멸해도 끝나지 않음(해체해야 함), 방어팀 전멸 → 공격 승, 폭발 → 공격 승, 해체 → 방어 승. 라운드가 끝난 뒤에는 설치·해체·폭발이 일어나지 않고, 폭발·해체는 한 번만 처리됩니다.
  폭발은 22 m 안의 모두에게 거리에 비례한 피해(최대 500, 벽이 막지 않음, 처치 보상 없음). 승패 보상은 기존 경제 규칙대로.
- **하프타임**: (승리 라운드 − 1)라운드 뒤 공수 교대(스폰도 바뀜). 자금은 시작 금액으로, 장비는 기본 지급으로 초기화됩니다.
- **HUD**: 내 진영(공격/방어), C4 상태(공격팀만 운반자·떨어짐을 앎), 설치 후 사이트·남은 시간, E키 안내, 내 설치/해체 진행 막대. 결과에 'C4 폭파'/'C4 해체' 표시.
- **임시 표현**: C4 모델 파일이 없어 작은 상자·키패드·전선으로 된 절차적 모델(설치 후 빨간 불이 점점 빠르게 깜빡이며 삐 소리), 폭발은 빛 덩어리 + 합성음입니다.

### 투척 장비 (FLASH-01 섬광탄 · SMOKE-01 연막탄)

수치는 `config.ts`의 `GRENADE_CONFIG`, 로직은 `combat/Grenades.ts`.

- **사용**: **4**(조작 설정 '투척 장비')로 섬광탄을 꺼내고, 한 번 더 누르면 연막탄으로 바꿉니다. 꺼내는 데 0.35초, 왼쪽 클릭으로 던지면 무기로 돌아옵니다. 1·2·3·Q·휠로 집어넣습니다. 라운드 진행 중에만 던질 수 있습니다.
- **비행**: 시선 방향 15 m/s + 위로 2.2 m/s + 내 속도, 중력, 맵 충돌에 튕기고 굴러가다 멈춤(사람에게는 튕기지 않음).
- **섬광**: 던진 뒤 1.6초에 터짐. 플레이어와 봇 모두 거리(24 m에서 0), 시선 각도(정면 최대 4.5초, 등지면 짧게), 벽 차폐를 따져 실명 시간이 정해집니다.
  플레이어는 화면이 하얗게 되었다가 마지막 1.4초 동안 걷힙니다. 봇은 실명 중 아무도 보지 못하고 쏘지 않으며 끝나면 다시 탐지합니다. 아군도 맞습니다.
- **연막**: 멈춘 뒤 터짐(최대 3초). 1.1초에 걸쳐 반지름 3.6 m로 퍼지고 16초 유지(마지막 2.5초 동안 옅어짐). 봇의 시야선이 구름을 지나면 보지 못하고, 플레이어는 구름 자체와 안에 있을 때 회색 막으로 가려집니다.
  성능: 구름 하나에 스프라이트 22개, 시야 판정은 선분-구 계산뿐.
- **보유**: 섬광 2개·연막 1개까지, HUD 무기 칸 위에 개수. 생존 시 남은 것 이월, 사망 시 소실, 라운드 전환 때 날아가는 것·구름·실명 모두 정리.
- **임시 표현**: 모델 파일이 없어 작은 원통(1인칭·월드), 섬광 빛 스프라이트, 회색 연막 스프라이트, 합성 효과음(핀·튕김·폭음·연기 분출)을 씁니다.

### 봇 전술 (C4 목표)

`ai/TacticalMap.ts`(맵마다 한 번 분석) + `ai/TacticalDirector.ts`(초당 2번 계획) + `Bot`의 명령 수행.

- **맵 분석**: 내비 격자와 충돌로 사이트마다 설치 가능 칸, 사이트 주변 고리(9~17 m)의 방향별 진입로, 옆에 엄폐물이 있고 진입로가 보이는 대기 지점을 계산합니다(손으로 찍은 경로점 없음).
- **공격**: 라운드마다 목표 사이트 선택, 진입·지원·운반자는 주 진입로, 한 명은 다른 진입로로 우회. 주 그룹이 진입로에 모이면(최대 30초) 사이트를 점령하고 운반자가 설치.
  설치 후 사이트 주변 엄폐 지점에서 방어팀 진입로를 지킵니다. 떨어진 C4는 가장 가까운 공격 봇이 회수해 설치하러 갑니다.
- **방어**: A 2명·B 2명(+ 다섯째는 중앙), 엄폐 지점에서 진입로를 봄. 아군 봇이 실제로 본 적이 사이트 근처면 그쪽으로 회전. 설치가 알려지면 가장 가까운 봇이 해체하고 나머지는 엄호.
- **이동 중 교전 규칙**: 명령을 받아 이동 중인 봇(목표 지점이 아직 15 m 넘게 남았거나, 떨어진 C4를 주우러 가는 중)은 30 m보다 먼 적을 새로 보면 팀에 알리기만 하고 멈춰서 결투하지 않습니다.
  30 m 안의 적, 자리를 지키는 봇은 기존과 같이 교전합니다. 명령이 있는 봇은 12 m보다 멀리서 놓친 적을 쫓아가지 않고 명령으로 돌아갑니다.
  (창고 맵은 두 스폰 사이 중앙 도로에 직선 시야가 있어, 이 규칙이 없을 때 라운드 시작 즉시 57 m 거리의 중앙 난타전이 매번 일어났습니다.)
- **공정성**: 시야·반응·조준 실력은 기존 그대로, 벽 너머·연막 너머는 못 봄. 계획은 팀이 알 수 있는 정보(자기 위치, 아군이 본 적, 공개된 설치)만 사용. 순간이동 없음.
- **성능**: 경로 탐색은 명령이 바뀌거나 길이 끊겼을 때만(같은 명령은 최소 2초 간격). 테스트에서 봇당 초당 1회 미만.
- **재현성**: 링크에 `?seed=숫자`를 붙이면 봇의 무작위 선택이 고정됩니다(테스트용).
- 전멸전·개인전에서는 기존 순찰 AI 그대로입니다.

## 멀티플레이

설계·한계: [`docs/multiplayer.md`](docs/multiplayer.md). 로비의 **MULTIPLAYER**(멀티플레이 탭)에서 닉네임과 모드(데스매치 / 5대5 라운드전)를 고르고
**빠른 참가**, **방 만들기**(5자리 코드를 친구에게), **코드로 참가**, **방 목록**(열린 방·인원, 참가 버튼) 중 하나 → 플레이 버튼(또는 로비의 경기 입장).
방 정보에는 참가자·방장·(라운드전) 팀이 보입니다. 연결이 끊기면 싱글플레이로 돌아오고 로비에 안내와 **같은 방에 다시 참가** 버튼이 나옵니다.

- 데스매치 최대 8명, 라운드전 최대 10명. 빈 자리는 봇이 채웁니다(사람이 봇 자리를 맡음). 라운드전은 사람이 적은 팀으로 배정.
- **방장 브라우저가 경기를 진행**합니다(봇·규칙·판정·돈·C4). 서버(`server/mp`)는 방 관리와 중계만 해서 무료 플랜으로 충분합니다.
  다른 사람은 자기 캐릭터를 자기 화면에서 바로 움직이고, 탄은 방장이 그 사람이 보던 시점으로 되돌려(지연 보정) 판정합니다.
- 점수판의 킬·데스는 그 자리를 지금 조종하는 사람의 기록입니다. 봇 자리를 넘겨받으면 0부터 시작하고, 나가면 봇이 자기 기록을 되찾습니다(팀 라운드 점수와 돈은 그대로).
- 방장이 나가면 다음 사람이 방장이 되고 경기는 새로 시작합니다. 방장은 판정을 맡으므로 조작이 가능합니다(친구끼리 하는 용도).
- 로컬: `npm run build && npm run build:mp && npm run start:mp` → http://localhost:8080. Render에서는 `tactical-fps-mp` 서비스 주소에서 플레이합니다.

## GRID 스킨 · 상점 · 보관함 · 크레딧

설계·조사·API 계약: [`docs/grid-economy.md`](docs/grid-economy.md). 전투 코드와 독립된 모듈(`src/economy`, `src/skins`, `src/ui/GridStore.ts`)이고,
라운드 구매 자금($, `game/Economy.ts`)과는 이름·화면·저장 키가 완전히 다릅니다.

- **스킨 32종**(대상별 기본 외형 8 + 판매 24): AR-01·SR-01·SMG-01·SG-01·PIS-01 총기, M9 총검, 장갑, 전투복. 외형은 세라코트·아노다이즈·직물 색 같은 실제 마감(색·금속성·거칠기)으로,
  모델 모양·손 위치·애니메이션·피격 판정·무기 수치는 바뀌지 않습니다. 희귀도는 표시와 가격에만 쓰입니다.
- **적용**: 총기·칼은 1인칭 모델(파일 재질의 스킨 복사본을 스킨마다 한 번만 만들어 재사용), 장갑은 1인칭 손, 전투복은 1인칭 소매·하체.
  봇의 팀 색은 그대로라 피아 식별에 영향이 없습니다. 플레이어의 3인칭 월드 모델은 이 게임에 없습니다.
- **크레딧(CR)**: 시작 500. 팀전 완료 100(+승리 150, 처치당 10 최대 100), 데스매치 완료 60(+1위 80, 처치당 5 최대 50).
  훈련장·대결 포기·중도 이탈·1분 미만 경기는 0. 같은 경기는 한 번만 정산. 결과 화면에 지급액 표시. 수치는 `economy/EconomyRules.ts`.
- **일일 미션**: 경기 1회 완료(100), 적 10명 처치(150), 라운드 3회 승리(150), SR-01로 3명 처치(200). 완료와 수령은 별개, 수령은 한 번. 기기 날짜가 바뀌면 초기화(온라인에서는 서버 날짜).
- **저장**: 계정 서버가 없으면(지금의 정적 사이트, 개발 서버) **오프라인 기록** — `localStorage`의 `grid.account.v1`(revision으로 다른 탭과의 충돌 감지), 이 브라우저에만 있고 서버 검증은 없습니다.
- **GRID 계정 서버**(구현 · **꺼 둠**, `VITE_GRID_ACCOUNTS=1`로 켬 · 미배포): [`docs/grid-account-server.md`](docs/grid-account-server.md). Node 서버(`server/`)가 게임과 `/api`를 같은 출처로 제공하고 PostgreSQL에 저장합니다.
  GRID 페이지 위 계정 줄에서 가입·로그인하면 크레딧·스킨·장착·미션을 서버 계정에서 불러오며, 새로고침·다른 브라우저에서도 같습니다.
  구매는 서버 가격·서버 잔액으로 한 트랜잭션(멱등 키), 오프라인 기록은 계정으로 **옮겨지지 않습니다**(로그인 시 알림).
  경기 결과를 서버가 검증할 수단이 아직 없어 **온라인 계정은 경기·미션으로 크레딧을 얻지 않습니다**(클라이언트 보고는 403). 거래는 미구현(`economy/server/TradeService.ts` 메모리 모델만).
  로컬 실행: `DATABASE_URL=postgres://… npm run build && npm run build:server && npm start` → http://localhost:8080, 또는 서버를 띄운 채 `GRID_API_PROXY=http://127.0.0.1:8080 npm run dev`.
  테스트(`tests/grid-account-*.test.mjs`)는 `GRID_TEST_DATABASE_URL` 또는 로컬 PostgreSQL(`initdb`)이 필요하고, 없으면 건너뜀으로 보고됩니다.

## 타격감 · 조작 설정

- **혈흔**: 표적(몸)을 맞히면 맞은 자리에 피 안개, 튀어 떨어지는 핏방울, 바로 뒤 4 m 안의 벽과 아래 바닥에 핏자국이 남습니다.
  헤드샷은 더 많이 튑니다. 피격 부위는 붉게 번쩍입니다. 핏자국은 리스폰·맵 전환 때 지워집니다 (`fx/BloodEffects.ts`, 드로우콜 3개).
- **소리**: 몸에 맞으면 콘크리트 탄착음 대신 묵직한 살 타격음(`impact.flesh`)이 맞은 위치에서 나고, 기존 명중 확인음(몸/머리)이 함께 납니다.
- **조작 탭**: 마우스 **감도**(0.2~4, 기본 1) 슬라이더와 **키 설정**(앞/뒤/좌/우, 점프, 걷기, 앉기, 재장전, 무기 1·2·3, 이전 무기, C4 설치/해체(E), 투척 장비(4), 살펴보기).
  키 버튼을 누르고 원하는 키를 누르면 바뀌고, 이미 쓰는 키면 두 동작이 서로 바뀝니다. Esc는 취소, Esc·F3·F4는 지정할 수 없습니다. "기본값으로"로 되돌립니다.
  감도·키는 기존 설정과 따로 `tactical-fps.controls.v1`에 저장됩니다(기존 설정 형식 유지).
- **1인칭 무기 위치**: CS처럼 화면 오른쪽 아래에서 거의 정면을 겨누는 배치(모델은 그대로, 위치·각도만 조정).

## 전투 비주얼 (총구 화염 · 탄피 · 탄착 · 킬 표시)

모두 화면 연출일 뿐이며 피해량·연사 속도·탄창·재장전·반동·감도·히트 판정은 바뀌지 않습니다. 네트워크로 보내지 않습니다(각 클라이언트가 이미 받는 사격 결과로 직접 그림).

- **1인칭 총구 화염** (`weapons/view/MuzzleFlash.ts`): 총구(`Muzzle` 앵커)에 붙는 정면 별 + 소염기 갈래 화염 + (중·고) 연기 한 줄기.
  AR 짧고 강함, SMG 작고 빠름, 권총 짧은 팝, 샷건 넓고 묵직함, 저격총 크고 머즐 브레이크 옆 분사. 0.03~0.07초 뒤 사라지며 화면을 가리지 않습니다.
  **고품질**에서만 짧은 월드 조명(`muzzleLight`, 로드 시 1개 생성, 사격 순간에만 켜짐 — 지속 조명 없음).
- **탄피** (`fx/ShellCasings.ts`): 무기 배출구(`Ejection_Port` 노드 또는 `fit.ejectPort`)에서 오른쪽(샷건은 모델의 왼쪽 볼트 창) 위로 튀어나와
  중력·회전·바닥 튕김 후 옆으로 누워 5초 뒤 사라집니다. 탄종별 크기·색(5.56 황동, 9 mm, .338 대형, 12게이지 빨간 탄피).
  샷건은 펌프, 저격총은 볼트를 당길 때 나옵니다. InstancedMesh 1개(최대 48개, 오래된 것부터 재사용). **저품질에서는 끔.**
- **탄착** (`fx/ImpactEffects.ts`): 맵의 실제 표면 재질(충돌 지오메트리의 `surface` 속성, `CollisionWorld.surfaceAt`)에 따라
  금속·유리는 불꽃, 콘크리트·벽돌·흙·나무는 재질 색 먼지와 파편, 바닥은 더 큰 먼지. 깊이 테스트(벽 너머로 안 보임), 풀 4개(드로우콜 4개).
  저품질 = 탄흔 + 작은 먼지, 중간 = 불꽃·파편 절반, 고품질 = 전부. 자동 품질이 낮아지면 장식 효과부터 줄어듭니다.
- **명중·헤드샷·킬**: 서버(호스트)가 확정한 결과만 표시. 몸통 = 흰 X, 헤드샷 = 빨간 X + 작은 링, 킬 = 굵고 큰 X + 큰 링.
  매치가 인정한 킬에는 기존 킬 확인음과 함께 조준점 아래 짧은 "처치" 표시. 아군·훈련 표적 쓰러뜨림은 킬 표시 없음(기존 규칙 그대로).
- **총기 표면** (`weapons/view/WeaponSurface.ts`): 텍스처·UV가 없는 GLB 재질에 셰이더로 금속 미세 가공 결·마모 반점, 폴리머 미세 돌기를 더합니다
  (색·금속성·거칠기 값은 그대로, 스킨 사본에도 동일 적용). 모델링에 쓰고 남은 커터 메시(흰색)는 어두운 구멍으로 표시. 모델·디자인은 그대로입니다.
- **장갑**: 손등 보호대 3분할, 왼손 손목 스트랩(스킨 색 그대로 적용).

## 전투 몰입감 (카메라 · 무기 무게 · 조명 · 공간음 · HUD)

- **카메라 움직임** (`player/CameraMotion.ts`): 걸음마다 눈높이가 살짝 내려가고 좌우로 이동·기울어짐(달리기 > 걷기 > 앉기, 최대 약 1 cm·0.2°),
  착지 시 낙하 속도만큼 짧게 꺼짐(버니합은 약하게, 지붕에서 떨어지면 분명하게, 최대 7.5 cm), 공중에서는 흔들림 없음, 정지 시 아주 약한 호흡.
  조준(스코프) 중에는 25 %로 줄어듭니다. **카메라의 위치와 롤만** 바뀌고 피치·요는 그대로라 조준점·탄도·감도·반동은 전혀 바뀌지 않습니다.
- **무기 무게** (`WEAPON_WEIGHT`, ViewModelLayer): AR 기준, SMG 가볍고 빠름, 권총 작게, 샷건 묵직하게, 저격총 가장 무겁게(시선을 늦게 따라오고 착지에 더 깊이 내려감).
  걸음 흔들림은 카메라의 걸음 주기와 맞물리고, 공중에서는 상승·낙하에 따라 살짝 뜨거나 가라앉습니다. 사격·재장전·교체 동작과 밸런스는 그대로입니다.
- **조명** (`world/SkyOcclusion.ts`): 맵 로드 시 한 번 플레이 구역의 하늘 가시성을 3D 텍스처로 굽고(창고 약 0.1초, 서울 약 0.3초),
  맵 재질의 하늘 보조광·반사만 지붕 아래에서 줄입니다(창고 50 %, 서울 64 %까지). 실내가 실내답게 어두워지지만 **플레이어·봇·무기는 그대로 밝아** 적 가시성은 그대로입니다.
  1인칭 손·무기도 실내에서 최대 25 % 어두워집니다. 저품질은 굽지 않습니다(모든 표면 기존 밝기). 실시간 조명 추가 없음.
- **공간음** (`AudioEngine` 하나에 추가): 실내(짧고 촘촘한 잔향)·실외(길고 옅은 잔향 + 먼 건물 반사)를 시선 위·주변 레이 5개로 0.25초마다 판단해 서서히 섞습니다.
  먼 총성일수록 잔향 비중이 커지고 고음이 줄어듭니다(가까운 총성은 마른 소리). 자기 발소리(달리기만 들리게, 걷기·앉기는 작게)·착지음·탄피가 바닥에 떨어지는 소리 추가.
  새 소리는 전용 음성 그룹(`env`, 최대 4)이라 총성·탄착음을 밀어내지 않고, 탄피 소리는 45 ms에 하나만. 다른 플레이어의 발소리는 내지 않습니다(위치 노출 방지).
- **HUD**: 피해를 받으면 잃은 체력이 빨갛게 잠시 남았다가 줄어듦, 탄창 잔량 막대(부족하면 경고색), 무기 교체 시 무기 패널 강조, 킬 피드 새 항목만 미끄러져 들어옴, 헤드샷(HS) 강조, 숫자 가독성 그림자.

## 훈련 표적

맵을 불러오면 시작 스폰 앞에 사람 크기(약 1.78 m)의 훈련 표적이 놓입니다 (고정 4개 + 좌우로 움직이는 1개).

- **배치**: 맵 파일에 표적 위치가 없으므로 `TrainingRange.ts`의 `TARGET_SLOTS`(스폰 기준 거리·좌우)를 맵 충돌로 검사해
  바닥이 있고, 서 있을 공간과 뒤로 쓰러질 공간이 있고, 스폰에서 머리·몸통이 보이는 곳에 둡니다. 안 되면 1 m씩 당기고,
  끝내 안 되면 그 칸은 비우고 콘솔에 사유를 남깁니다 (테스트는 맵마다 3개 미만이면 실패).
- **판정**: 기존 `Damageable` 인터페이스를 구현해 `HitscanSystem`에 등록합니다. 벽 판정·부위 배율·거리 감소·무기 수치는 기존 코드 그대로입니다.
  총알은 **화면에 그려지는 삼각형 그대로**(BVH) 검사하므로, 흔들리거나 쓰러지는 중에도 보이는 곳이 맞는 곳입니다.
  머리 = 머리, 목·몸통·골반 = 몸, 팔·다리 = 팔다리.
- **체력 100**: AR-01 몸 4발 / 머리 1발, SR-01 몸 1발, 카람빗 3번. 맞으면 맞은 부위가 잠깐 밝아지고 맞은 방향으로 흔들립니다.
- **쓰러짐·복귀**: 0.35초 동안 뒤로 쓰러지고, 3초 뒤 0.5초 동안 일어나 체력 100으로 돌아옵니다. 쓰러져 있는 동안은 총알이 통과합니다.
  F4(리스폰)와 맵 로드 때 모두 초기화되고, 맵을 바꾸면 이전 표적은 판정에서 빠지고 GPU 자원이 해제됩니다.
- **이동 표적**: 3 m 구간을 최대 1.5 m/s로 왕복합니다 (고정 틱에서 계산, 같은 입력이면 같은 위치).
- **명중 표시**: 조준점 주변 X (머리는 빨강, 처치는 크게). 명중 확인음은 몸(둔탁한 소리)·머리(금속성 소리) 2종.
  F3 정보창에 마지막 명중(부위·피해·거리)이 나옵니다. 표적에는 탄흔을 남기지 않습니다(쓰러지면 공중에 뜨므로).
- 표적은 그림자를 받기만 합니다. 맵 그림자는 로드 때 한 번만 그리므로, 움직이는 표적의 그림자는 남은 자국이 됩니다.
- 표적은 이동 충돌에 포함되지 않아 플레이어가 통과할 수 있습니다 (이동 결과를 바꾸지 않기 위함).

## 맵 그래픽 (표면 재질)

맵 GLB에는 텍스처와 UV가 거의 없습니다(서울 1004개 프리미티브 중 UV 12개). 그래서 이미지 텍스처 대신:

- 재질 이름으로 표면 종류를 정합니다 (`SurfaceMaterials.ts`의 `RULES`). 예: `*Asphalt*` → 아스팔트, `*Brick*` → 벽돌,
  `*Glass*` → 유리, `*Paver*`·`*Plaza_Block*` → 보도블록. 새 재질은 이름 규칙에 맞추거나 `RULES`에 한 줄 추가하면 됩니다.
- 종류별 roughness / metalness와, 월드 좌표로 투영한 절차적 디테일(톤 변화·얼룩, 미세 입자 범프, 벽의 빗물 자국,
  바닥·지붕의 먼지, 도로 도색 마모, 벽돌 줄눈, 보도블록·콘크리트 슬래브 이음매)을 셰이더에 추가합니다.
  노이즈 텍스처 1장(256², 코드로 생성)을 두 배율로 섞어 반복 무늬가 보이지 않게 합니다. 드로우콜은 늘지 않습니다.
- 하늘 반사(환경맵)는 유리·금속·차량 도장·물에만 연결합니다. 거친 표면은 하늘 반구광으로 충분합니다.
- 화질별: **낮음** = 재질 값만 (추가 픽셀 비용 없음, 반사 없음) · **중간** = 디테일(텍스처 2회 샘플) + 반사 · **높음** = 미세 입자 레이어 추가.

## 1인칭 팔과 다리

- **팔·손** (`FirstPersonArms.ts`): 무기 모델의 `Grip_R`/`Grip_L` 앵커에 붙는 절차적 장갑·소매. 무기 모델·앵커·위치는 그대로입니다.
  왼손은 총열 덮개를 C자로 감싸 엄지와 손가락 끝이 화면에 보이고, 재장전 때 탄창을 잡는 동안 손가락 끝을 펴서 탄창을 관통하지 않습니다.
  소매는 타원 단면 + 주름 + 립스탑 원단 텍스처·노멀맵, 손목 커프와 벨크로 탭.
- **다리** (`FirstPersonBody.ts`): 월드 장면의 하체 모델. 플레이어 컨트롤러 값을 읽기만 하므로 이동 속도·점프·충돌·카메라는 바뀌지 않습니다.
  - 2관절 IK, 이동 거리로 진행하는 걸음 주기(디딤 발은 땅에 고정, 달리기에는 공중 구간), 앉기·점프 자세.
  - 이동 중에는 몸이 시선을 따라가고, 옆·대각선 이동 시 하체를 최대 57° 비틀어 다리가 교차하지 않게 합니다. 정지 중에는 시선이 45° 이상 돌아가야 몸이 돕니다.
  - 허리 위로는 만들지 않아 카메라와 최소 0.5 m 떨어져 있습니다(근거리 클리핑 없음). 치수는 충돌 캡슐(키 1.8 m, 반지름 0.35 m)에 맞췄습니다.
- **다른 플레이어용 전신 모델은 아직 없습니다.** 멀티플레이·원격 플레이어 시스템이 없기 때문이며, 추가할 때는 이 1인칭 하체와 별개의
  3인칭 전신 모델(머리·상체 포함, 무기를 손에 든 자세)이 필요합니다.

## 맵 디테일 (코드로 덧입히는 드레싱)

맵 GLB 파일은 그대로 두고, 로드할 때 맵 자신의 노드 배치(건물·바닥·엄폐물 박스)를 읽어 디테일을 코드로 만들어 붙입니다
(`world/dressing/MapDressing.ts`, `PropKit.ts`, `SignAtlas.ts`). 시드 고정이라 모든 클라이언트·모든 로드에서 똑같습니다.
만든 부품은 재질별로 하나의 메시로 묶여 기존 맵 파이프라인(재질별 병합, 충돌, 표면 종류, 하늘 가림, 그림자, 봇 내비 그리드)에 그대로 들어갑니다.

- **서울**: 건물 블록의 거리 쪽 면마다 1층 상가(조명이 켜진 실내가 보이는 쇼윈도, 알루미늄 프레임, 출입문, 실제 한국 상가 간판 16종 — 행복약국, 서울안경원, 맛나분식, 한빛부동산 …),
  일부 차양, 층 구분 띠·창문(프레임·창턱), 창 밑 에어컨 실외기, 모서리 우수관, 세로 간판(학원·치과·노래연습장 …), 옥상 실외기·물탱크·환기구,
  커튼월 멀리언(유리 건물), 석조 청사의 기둥·코니스, 전봇대(변압기·도로 표지판)와 늘어진 전선, 도로 가장자리 배수구·맨홀.
- **창고 지구**: 건물·외벽의 철골 기둥(넓은 곳에만)·띠보, 처마 밑 배관·전선관·브래킷, 산업용 벽등, 노란 하단 보호판, 바닥 보행선,
  구역 표지판(A동·B동·적재 구역·지게차 주의 …), 루버 환기구, 지붕 덮인 통로의 철골 장선·케이블 트레이·배관·매달린 조명,
  B 하역장 앞 빗금 구역, 넓은 바닥 쪽 벽을 따라 팔레트 랙(파랑/주황, 적재물), 팔레트 더미, 빈 드럼통, 핸드 파레트 트럭.
- **배치 규칙**: 바닥 소품은 벽에 붙여, 앞에 6.5 m 이상 트인 곳에만(통로를 좁히지 않음). 스폰·폭파 지점·엄폐물 주변·경사로·문 앞 금지.
  소품끼리 틈은 막히거나 1.3 m 이상(끼이는 틈 없음). 머리 높이 아래 벽 부착물은 얇게.
- **충돌 레이어**: `Dress_…`는 플레이어·총알 모두 막고 봇 내비에 반영, `DressDeco_…`(전선·차양·바닥 도색·배수구)는 시각 전용.
  저품질은 시각 전용 레이어만 빼며, **충돌은 모든 품질·모든 클라이언트에서 동일**(멀티플레이 안전).
- 재질 이름은 기존 표면 분류(`SurfaceMaterials`)를 따르므로 탄착(금속 불꽃·목재 파편·콘크리트 먼지)과 소리가 재질에 맞게 나옵니다.
- 비교용: 주소에 `&dressing=none`을 붙이면 파일 그대로의 맵.
- 비용(헤드리스 측정): 서울 드로우콜 168→190, 삼각형 42.0만→45.3만, 생성 약 0.06~0.16초 / 창고 87→111, 10.8만→13.1만, 약 0.05~0.14초. GLB 파일 크기 변화 없음.

## 맵 규칙 (Blender 노드 이름)

맵은 노드 이름 접두어로 분류되며, 규칙은 맵마다 `src/maps.ts` 에 있습니다.

| 분류 | 서울 | 창고 지구 | 동작 |
| --- | --- | --- | --- |
| 스폰 (Empty) | `ATK_SpawnPoint_*`, `DEF_SpawnPoint_*` | 같음 | 공격 스폰 가운데에서 시작 |
| 숨김 | `TPL_*`, `CG_TPL*`, `Cube*` | `Tpl_*`, `Cube`, `Ground_Pebble_Emitter` | 원점에 놓인 템플릿, 파티클 방출용 보조 메시 → 표시·충돌 없음 |
| 플레이어 차단벽 | `Boundary_*` | – | 보이지 않음, 이동만 막고 **총알은 통과** |
| 충돌 없음 | 원경(`Backdrop_`, `Skyline_`, `Mountain_`, `Far_` …), 청계천 갈대·버드나무, 바닥 도색 | 자갈·케이블·간판 등 | 보이지만 통과 |
| 구역 표시 | `Zone_*` | `Zone_*` | 기본 숨김, F3로 표시 |
| 나머지 | | | 렌더링 + 충돌 + 총알 차단 |

**새 맵 추가**: GLB를 `public/maps/` 에 넣고 `src/maps.ts` 의 `MAPS` 에 항목 하나를 추가하면 시작 화면 선택 목록에 나타납니다.
Blender 파일에 장면이 여러 개면 **활성 장면**(내보낼 때 선택된 장면)이 로드됩니다.

## 성능 설계

- 메시를 머티리얼별로 병합: 서울 1308개 → 168 드로우콜, 창고 지구 586개 → 88 드로우콜
  (공간 단위로 더 쪼개는 방식도 측정했지만 삼각형은 20%만 줄고 드로우콜이 2~3배가 되어 채택하지 않음)
- 정적 맵이므로 그림자 맵은 로드 시 **한 번만** 렌더링 (플레이 구역에만 맞춰 해상도 확보)
- 충돌은 BVH(three-mesh-bvh)로 처리 (서울 약 29만, 창고 지구 약 10만 삼각형). 원경·갈대·버드나무는 충돌에서 제외
- 1인칭 무기·손은 작은 환경 반사맵(시작 시 1회 생성)으로 재질감 표현
- 맵 표면 디테일은 셰이더 안에서 계산(텍스처 1장 공유, 드로우콜 증가 없음). 저사양은 셰이더 패치·반사 없이 재질 값만 조정
- 1인칭 하체는 뼈·재질별로 병합(드로우콜 약 16개)하고, 정면을 볼 때는 시야 밖이라 대부분 그려지지 않음
- 저사양(`low`): 픽셀 비율 1, 그림자·안티앨리어싱 끔
- HUD는 값이 바뀔 때만 DOM을 갱신
- 전투 이펙트(총구 화염·탄피·탄착·트레이서)는 모두 미리 만든 InstancedMesh 풀 재사용, 프레임당 할당 없음, 개수 상한 고정
- 하늘 가시성은 로드 시 1회 굽기(최대 4.8만 셀), 셰이더에서 3D 텍스처 1회 조회. 카메라 움직임은 프레임당 약 0.1 µs

## 배포 (Render 정적 사이트, 무료)

저장소 루트의 `render.yaml` 에 `tactical-fps` 정적 사이트가 정의되어 있습니다
(`npm ci && npm run build` → `dist/` 공개).

1. [Render](https://render.com)에서 **New → Blueprint** 를 누르고 이 저장소를 고릅니다.
   이미 Blueprint를 연결해 두었다면 기본 브랜치에 병합되는 순간 자동으로 추가됩니다.
2. 배포가 끝나면 `https://tactical-fps-xxxx.onrender.com` 주소로 접속합니다.

정적 사이트라 서버처럼 잠들지 않고, 바로 열립니다.

GRID 계정 서버(Node + PostgreSQL)는 **꺼 두었습니다**(코드만 유지). 게임은 오프라인 기록만 쓰고 계정 줄·서버 확인이 없습니다.
다시 켜려면 `VITE_GRID_ACCOUNTS=1`로 빌드하고 `render.account-server.yaml`의 DB·웹 서비스를 루트 `render.yaml`로 옮깁니다(유료).
자세한 내용은 [`docs/grid-account-server.md`](docs/grid-account-server.md).
