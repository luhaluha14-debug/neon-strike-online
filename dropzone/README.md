# NEON STRIKE: DROPZONE

PC와 모바일 브라우저에서 같은 코드로 돌아가는 3D 배틀로얄입니다. 봇과 하는 오프라인 매치와, 서버에 붙는 **온라인 대전(솔로·듀오·스쿼드)**을 지원합니다.
모든 무기, 맵, 캐릭터, UI, 사운드는 이 프로젝트를 위해 새로 만든 오리지널입니다. 사운드는 Web Audio로 실시간 합성하며 외부 에셋 파일을 쓰지 않습니다.

## 실행

```bash
cd dropzone
npm install
npm start                        # http://localhost:8090  (개발 빌드: F3 디버그)
NODE_ENV=production npm start    # 릴리스 빌드 (디버그 기능 비활성화)
npm test                         # 시뮬레이션 + 온라인 서버 테스트 (44개)
```

같은 와이파이의 휴대폰에서는 서버 콘솔에 표시되는 `http://192.168.x.x:8090` 주소로 접속합니다.
온라인 대전은 이 서버로 접속했을 때만 됩니다 (정적 파일만 올린 곳에서는 버튼이 꺼집니다).

## 온라인 서버 배포 (Render 무료 플랜)

1. 이 저장소를 GitHub에 올린 상태에서 [Render](https://render.com)에 로그인합니다.
2. **New → Blueprint** 를 누르고 이 저장소를 고릅니다. 루트의 `render.yaml`이 `dropzone` 폴더를 Node 웹 서비스로 만듭니다
   (`npm install` → `npm start`, `NODE_ENV=production`, 헬스 체크 `/health`).
3. 배포가 끝나면 `https://dropzone-xxxx.onrender.com` 주소가 생깁니다. PC와 휴대폰에서 이 주소로 접속하면 같은 서버에서 만납니다.
   WebSocket은 같은 주소의 `/ws`를 씁니다 (https면 자동으로 wss).
- 무료 플랜은 15분 동안 접속이 없으면 잠들고, 다음 접속 때 깨어나는 데 30~60초 걸립니다.
- 다른 호스팅(Fly.io, Railway, VPS)도 `cd dropzone && npm install && npm start`와 `PORT` 환경 변수만 있으면 됩니다.

## 온라인 대전

- **빠른 매칭**: 모드(솔로/듀오/스쿼드)를 고르면 열린 방에 들어가고, 20초 뒤(16명이 차면 3초 뒤) 시작합니다. 빈 자리는 봇이 채워 항상 24명입니다.
- **친구와 방 만들기**: 4글자 방 코드가 생깁니다. 친구가 코드를 입력해 들어오고, 듀오·스쿼드에서는 팀 줄을 눌러 팀을 고릅니다. 방장이 시작합니다.
- 서버가 권한을 가집니다: 이동 위치, 탄약, 피해, 아이템, 사망, 자기장, 차량, 승리는 모두 서버의 `Match`가 판정합니다. 클라이언트는 입력 명령과 줍기·버리기 요청만 보냅니다.
  명령 값은 서버에서 범위를 검사하고, 한꺼번에 몰려 온 입력은 합쳐서 처리하므로 속도 핵이 통하지 않습니다. 멀리 있는 아이템은 주울 수 없습니다.
- 클라이언트는 같은 시드로 서버와 똑같은 **미러 매치**를 만들어 두고, 서버가 20 Hz로 보내는 스냅샷으로 상태를 맞춥니다.
  - 내 이동: 입력 즉시 로컬에서 예측하고, 스냅샷이 오면 서버 위치로 되돌린 뒤 아직 확인되지 않은 입력을 다시 적용합니다(재조정). 작은 오차는 0.15초에 걸쳐 부드럽게 보정합니다.
  - 다른 플레이어·차량·수송기: 약 100 ms 전 상태를 두 스냅샷 사이에서 보간해 그립니다.
  - 총성·명중·처치·아이템 변화 같은 이벤트는 스냅샷을 기다리지 않고 바로 보냅니다.
- 게임 중 연결이 끊긴 플레이어는 봇이 이어서 플레이합니다. 온라인에서는 개발자 치트가 동작하지 않습니다.

## 듀오 / 스쿼드

- 치명상을 입어도 서 있는 팀원이 있으면 **기절**합니다. 기절하면 천천히 기어갈 수 있고, 체력(출혈 게이지)이 줄어듭니다. 기절할 때마다 더 빨리 줄어듭니다.
- 팀원 옆에서 **F(소생)**를 누르고 6초 동안 가만히 있으면 체력 25로 살아납니다. 움직이거나 쏘면 취소됩니다.
- 팀원끼리는 피해를 주지 않습니다. 팀 전원이 기절하거나 죽으면 팀이 탈락하고, 같은 순위를 받습니다.
- 화면: 왼쪽 팀 목록(체력·기절·사망), 머리 위 이름표와 거리, 미니맵·지도의 번호 표시, 기절 화면과 출혈 게이지, 소생 진행 막대. 내가 죽으면 살아 있는 팀원을 관전합니다.
- 봇 팀원: 리더(사람 팀원 우선)를 따라 같은 곳에 착지하고, 주변에서 파밍하며, 적이 없을 때 기절한 팀원을 소생합니다. 기절한 봇은 팀원 쪽으로 기어갑니다.
PC 브라우저에서 `?touch=1`을 붙이면 모바일 조작 UI를 강제로 켤 수 있습니다.

## 기술 스택과 선택 이유

| 영역 | 선택 | 이유 |
|---|---|---|
| 렌더링 | three.js (WebGL) | PC·iOS·Android 브라우저에서 설치 없이 실행됩니다. 기존 NEON STRIKE와 같은 스택이고, 나중에 Capacitor로 앱 패키징도 가능합니다 |
| 게임 로직 | 순수 JS 모듈 (`shared/`) | DOM이나 three.js에 의존하지 않습니다. **같은 코드가 브라우저(오프라인)와 Node 서버(온라인 권한 서버)에서 그대로 돌아갑니다** |
| 서버 | Node + ws | 기존 서버와 같은 스택입니다. PC와 모바일이 같은 서버에 붙습니다 |
| 테스트 | `node --test` + Playwright | 시뮬레이션은 Node 단위 테스트로, 실제 화면은 헤드리스 Chromium으로 확인합니다 |

### 서버와 클라이언트의 역할 분리

- 클라이언트는 **입력 명령**(이동축, 시점 각도, 버튼)만 만듭니다. 사람과 봇이 같은 명령 형식을 씁니다.
- `Match`(shared/game.js)가 이동, 탄약, 피해, 줍기, 사망, 자기장, 승리를 **모두** 판정합니다. 오프라인에서는 브라우저가 이 코드를 직접 돌리고, 온라인에서는 서버가 같은 코드를 권한을 가진 쪽으로 실행합니다.
- 산탄 퍼짐 같은 무작위 요소는 `(플레이어, 발사 번호, 매치 시드)`로 시드를 만들기 때문에, 클라이언트 예측과 서버 결과가 일치합니다.
- 이동 코드(`stepBody`)는 순수 함수입니다. 클라이언트 예측과 서버 재조정(reconciliation)에 그대로 쓸 수 있습니다.

## 조작 (PC 기본값, 설정에서 모두 변경 가능)

| 키 | 동작 | 키 | 동작 |
|---|---|---|---|
| WASD | 이동 | Shift | 달리기 |
| Ctrl | 걷기 | Space | 점프 |
| C | 앉기 | Z | 엎드리기 |
| 마우스 왼쪽 | 발사 | 마우스 오른쪽 | 조준 |
| R | 재장전 | F | 줍기 |
| 1~4 / 휠 | 무기 슬롯 | H | 빠른 회복 |
| F (팀원 옆) | 소생 | | |
| Tab | 인벤토리 | M | 지도 |
| V | 1인칭/3인칭 | Alt | 자유 시점 |
| 5 | 투척물 (다시 누르면 종류 변경) | 조준 누른 채 던지기 | 짧게 던지기 |

수송기에서는 Space(또는 F)로 뛰어내립니다. 낙하 중에 아래를 보면 급강하하고, Space를 누르면 낙하산을 폅니다. 지면 55m 위에서는 낙하산이 자동으로 펴집니다.
지도(M)를 클릭하면 목적지 마커가 찍혀서 미니맵과 나침반에 표시됩니다.

차량: F 탑승/하차 · W/S 가속·브레이크·후진 · A/D 조향 · Space 핸드브레이크 · Shift 부스트 · 1~4 좌석 변경. 연료통은 차량 가까이에서 사용합니다.

모바일 조작: 왼쪽 화면은 떠다니는 가상 스틱이고, 가장자리 위로 밀면 달리기입니다. 오른쪽 화면은 드래그해서 시점을 돌립니다. 버튼은 발사(좌·우 2개), 조준, 점프, 앉기, 엎드리기, 재장전, 줍기, 무기 교체, 회복, 가방, 지도, 시점, 일시정지입니다.
설정의 **버튼 배치 변경**에서 버튼을 끌어 옮기고 크기를 바꿀 수 있습니다.
모바일 설정: 터치 감도, UI 크기, 버튼 크기, 버튼 투명도, 자동 사격, 조준 보조, 자이로, 진동, 자동 줍기.

## 알려진 한계 (다음 단계에서 다룸)

- 봇은 1층 지면 경로만 길찾기합니다. 2층과 옥상의 아이템은 사람만 주울 수 있습니다.
- 방어구와 부착물은 아직 없습니다 (PHASE 3~4).
- 봇은 아직 차량을 운전하지 않고, 탑승 중에는 사격할 수 없습니다.
- 온라인에서 차량 운전과 낙하 중 움직임은 예측하지 않고 서버 상태를 따라가므로, 핑만큼 조작이 늦게 반영됩니다. (걷기·달리기·점프는 예측됨)
- 내 총성·반동은 서버 이벤트가 도착할 때 재생됩니다 (핑만큼 지연).
- 서버는 모든 플레이어 위치를 보내므로, 시야 밖 정보 숨기기(월핵 방지)는 아직 없습니다.
- 스냅샷은 JSON을 WebSocket 압축(permessage-deflate)으로 보냅니다. 24명 방에서 한 명당 약 10 KB/s(압축 전 약 90 KB/s)입니다. 더 큰 규모로 가려면 바이너리 형식과 거리별 전송 빈도 조절이 필요합니다.
